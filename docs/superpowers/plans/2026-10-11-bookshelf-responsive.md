# 漫画书架响应与缓存优化计划

> 当前会话按 executing-plans 分阶段实施；先复现，最小修改，独立审查及最终流式门禁。已有开发、发布及同份ZIP交付授权沿用。

**目标：** 减少冷/暖封面加载的本地开销；翻页/返回不在输入回调中等待封面生成；目录与整页切换清除墨水屏残影，单卡继续局部刷新。

**基线：** 858d3b1 / 0.4.28，已有最多六条完整加载链和卡片大小PNG。设备未检测到，用户反馈首次/返回均慢但未分别计时。

**已读证据：** Cache默认list为每个缓存文件stat，_part_size对每个临时文件重复list；每次预算、取消可能重复此成本。GridWidget:set_page在按钮回调内publish_visible，暖缓存一次同步解码整页；ThumbnailLoader在SourceLoader回调内同步解码原图、缩放、写PNG。Grid show/翻页使用ui刷新，无法保证电子墨水清除灰度残影。

**方案：** 加并发增加内存和服务负担；邻页预加载不修输入阻塞和残影；推荐有界后台制图、低成本精确缓存预算和分批显示，切页用一次完整刷新。只改当前书架链，不增加预扫全部书库或额外依赖。

## 阶段一：精确预算不重复stat全部缓存

修改cache.lua；新增bookshelf_responsive_cache_spec.lua。默认文件适配器先按所有权筛选辅助文件名再stat；一次统计所有在写part的辅助文件，仍逐次读取真实字节。旧子进程回收、ZIP辅助、任意manifest nonce、错误stat回退、配额及删除所有权不变。

- [x] 原代码复现：3000缓存文件、六个part，预算/取消产生无关文件stat；保存失败输出。
- [x] 修改后无关文件stat为0，六part辅助统计一次目录遍历；已有Cache/容量/取消规格通过。

## 阶段二：操作先重绘，再显示封面

修改ui_cover_grid.lua和bookshelf.lua；新增bookshelf_responsive_grid_spec.lua。书架启用最多两张每帧的有界渲染队列，旧代次队列立即取消；UI切页先重建空卡并完整刷新，然后下一界面循环启动当前页。新目录show、翻页明确完整刷新；单卡刷新只限自身区域。尺寸信息优先用已验证缓存记录，未知本地图仍探测。

- [x] 复现按钮回调同步进入on_visible/解码、缺少完整刷新。
- [x] 真适配器测试：20卡→3卡、最后不足一页、快速连续翻页、返回/退出，旧回调不能画新页；每批最多两次封面渲染。

## 阶段三：大图制缩略图脱离输入线程

修改bookshelf_loader.lua和bookshelf.lua；新增bookshelf_responsive_thumbnail_spec.lua。使用既有Async后台能力，显式书架启用；按已预留PNG预算运行。按目标key合并相同制图；缓存/来源文件由父进程保护，直到工作完成或取消后回收才清除，迟到结果不发布；沿用既有PNG格式与尺寸键。

- [x] 复现Source回调同步制图，构造重入、合并和取消待回收用例。
- [x] 后台制图、错误/抛异常、零预算、共享源图、取消/回收、布局变化均通过；正文与历史默认行为不变。

阶段记录：Cache9、Grid14、Thumbnail44项，共67项当前专项通过；每阶段先观察旧实现失败再修改。源图、布局、取消后的继任任务与异常回收都有独立断言。默认正文/历史不启用后台Thumbnail；书架显式启用，沿用既有Async。

独立审查：两个P1（tickAfterNext只重绘不让出输入；Source缓存同步回调return nil提前释放整链槽）与一个P2（publish抛异常漏清理）均补RED→GREEN。调度改为重绘之后再正延迟20ms；读取固定官方UIManager五个原方法，模拟100ms有脏区重绘及额外异步重绘，确认批次之间轮询输入。同步源命中返回非nil保持整链槽，15卡最多六个PNG子任务。发布抛异常通知一次并释放源图/part。审查者独立复现并确认，无未解决阻断项。

# 阅读状态与局部提示刷新修复规划

> 当前代理按 superpowers:executing-plans 在本会话逐项实施；每个行为先复现失败，最终独立审查。

**目标：** 关闭去灰与亮度/对比度增强后显示原图，不再报告增强成功；未识别分格的页显示整页，下一页继续检测；提示更新只刷新文字区域。

**架构：** 复用已有 Reader、PanelSession 和 ReaderShell。分格入口快照保留阅读意图，单页检测失败释放该页会话后继续导航。提示留在原阅读 widget 中，只更新提示子节点和指定矩形，不重新建立 ImageWidget。

**技术栈：** Lua 5.1、KOReader 现有 widget/UIManager、现有 Python/Lupa 检查与严格117文件打包，无新依赖。

**依据：** 用户本次三条验收要求；基线 db785bf。现有6组相关规格通过。已核对设备导出 UIManager:setDirty 的 refreshregion 和 ui 模式，以及固定官方 FrameContainer/OverlapGroup 的 getSize/paintTo 契约。当前未检测到设备。

## 方案比较

| 方案 | 影响 | 选择 |
| --- | --- | --- |
| 关闭全部提示，检测失败退出 | 隐藏问题，无法满足下一页继续分格 | 不采用 |
| 重建独立阅读器/提示窗口体系 | 生命周期和触控变化较大 | 不采用 |
| 修正当前状态与原 widget 的局部刷新 | 不引入新依赖，保留既有处理和导航边界 | 推荐并实施 |

## 范围与边界

- 修改 ui_reader.lua：增强关闭和旧回调提示保护、无处理 profile 不标记成功、单页分格回退、跨页续检、主动退出与显示模式切换清理。
- 修改 ui_reader_shell.lua：提示子节点独立更新；显示、替换与消失只请求 ui 矩形刷新，旧页定时器不删除新页提示。
- 自动裁边和适屏属于用户另选的几何行为，保留；单纯裁边不显示增强成功。真正图像/源/分格渲染故障继续走现有错误处理，不伪装成正常无分格页。
- 不修改 OPDS、授权、设备设置、凭据、原生库、漫画原文件或其它格式。
- 首末页、反向翻页、连续未分格、重复触控、迟到结果、关闭/重开、设置禁用、提示期间气泡和动画是审查重点。
